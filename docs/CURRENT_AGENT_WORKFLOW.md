# Lutealark 当前 Agent 工作流与功能说明

## 1. 产品定位

Lutealark 是面向 ADHD 女性的周期感知型支持工具。它将对话、轻量行动、每日状态、周期信息和低压力工具放在同一体验中：先理解用户此刻的主要困难，再给出一个足够轻、可停止、不过度施压的下一步。

系统不把周期状态当作诊断，也不把用户的低能量、拖延或情绪波动解释为懒惰或不够自律。

## 2. 对话输入与上下文

每轮对话进入工作流前，会先完成输入标准化。工作流可使用以下上下文：

- 用户文字输入；
- 当前周期阶段、周期日、距下次月经天数、基础能量与缓冲模式；
- 当日用户主动记录的能量、情绪、身体感受和备注；
- 当前会话中的 `pending_action` 待确认动作；
- 图片附件的存在状态、图片附件对象，以及供多模态节点使用的图片 URL 列表。

每日记录只在用户确实有当天记录时作为参考；用户自评优先于周期推算。图片只用于用户明确请求的视觉环境支持，或用户仅上传环境图片时的图片环境路径。

## 3. 总体对话路由

```text
用户输入
  → 输入标准化
  → 是否存在 pending_action？
      ├─ 是：识别用户对当前邀请的回应
      │     ├─ 接受
      │     ├─ 拒绝
      │     ├─ 询问说明
      │     └─ 新请求
      └─ 否：识别本轮主要意图
            ├─ safety_crisis
            ├─ cycle_question
            ├─ task_difficulty
            ├─ emotion_support
            ├─ environment_support
            ├─ breathing_request
            ├─ daily_checkin_request
            ├─ focus_timer_request
            ├─ light_plan_request
            └─ smalltalk / 通用回复
```

每轮只按一个主要意图路由。危机内容优先级最高；明确要求打开某个功能时，直接进入对应功能；任务启动、排序、计划和推进困难优先进入任务分支，而不是被泛化为情绪支持。

## 4. 待确认动作机制

系统使用同一 Session 仅保留一个 `pending_action`，用于处理邀请后的自然语言确认。

支持的待确认动作包括：

- `offer_breathing`：邀请进行简短呼吸练习；
- `offer_focus_timer`：邀请开始轻专注番茄钟；
- `offer_light_plan`：邀请制定轻计划；
- `offer_daily_checkin`：邀请填写每日记录。

当用户回复“好”“可以”“行”“开始”等短确认时，系统在存在待确认动作的前提下优先将其理解为接受；“不用”“算了”“先不了”等理解为拒绝；询问内容或原理则进入说明回复；与当前邀请无关的新内容会清除旧邀请，重新进入意图识别。

接受后系统输出对应 `open_*` action；拒绝和说明不会强行打开工具，也不会继续施压。

## 5. 任务支持工作流

当用户的主要困难是写不动、开始困难、任务堆积、排序混乱、计划难落地或推进卡住时，进入任务支持分支。

```text
任务困难
  → 任务支持回复与上下文判断
  → 主动任务动作选择
      ├─ 轻专注邀请
      ├─ 轻计划邀请
      └─ 普通任务支持
  → 记录待确认动作（仅邀请路径）
  → 结果渲染
```

回复遵循“减少负担、只推进一个小步骤”的原则：不生成长任务清单，不同时提出多个工具，不把复杂现实问题压缩为单纯意志力问题。

## 6. 情绪支持工作流

情绪支持先确认体验，再用去羞耻化语言降低压力。它可以参考周期与每日记录，但不会将任何情绪简单归因于周期。

```text
情绪支持
  → 情绪支持回复与上下文判断
  → 主动支持动作选择
      ├─ 呼吸邀请
      ├─ 每日记录邀请
      └─ 普通情绪支持
  → 记录待确认动作（仅邀请路径）
  → 结果渲染
```

在缓冲模式、低能量、明显疲惫或焦虑时，建议会进一步缩短，并明确允许用户暂停、不解决问题或只停留在被陪伴的状态。

## 7. 明确功能请求

当用户明确表达要使用某项功能时，系统不再多轮邀请，直接返回相应 action：

| 用户目标 | Action | 前端结果 |
| --- | --- | --- |
| 开始呼吸训练 | `open_breathing` | 打开呼吸空间 |
| 填写今日状态 | `open_daily_checkin` | 打开每日记录 |
| 开始专注计时 | `open_focus_timer` | 打开并聚焦轻专注番茄钟 |
| 制定今日轻计划 | `open_light_plan` | 打开轻计划区域 |
| 查看周期 | `open_cycle` | 打开周期页面 |

`offer_*` 只代表对话中的邀请状态，不会自行导航；只有用户明确接受后才会返回对应 `open_*` action。

## 8. 图片环境支持工作流

图片环境支持的目标不是评价“整不整洁”，而是根据用户此刻可见的桌面、视线范围或准备开始的位置，找出一个轻量、可逆、容易尝试的视觉减负动作。

```text
environment_support
  → 是否附有可分析图片？
      ├─ 否：请求环境图片回复
      └─ 是：环境图片观察（多模态模型）
              → 环境图片观察标准化
              → 图片是否适合环境微调？
                  ├─ 是：图片环境支持回复
                  └─ 否：图片不适用回复
  → 结果渲染
```

多模态观察节点只输出受限结构化信息：图片是否可用、是否为环境场景、可信度、最多两项可见观察，以及一个建议聚焦点。后续脚本节点负责解析和门控，最终回复节点再生成温和自然的用户文案。

图片不清晰、不是环境场景、主要是人脸/聊天截图/隐私屏幕、无法可靠判断时，系统不会编造观察或给出具体整理建议，而是请用户提供更小的桌面或视线范围图片。纯声音、温度、气味和触感问题不依赖图片环境分析。

正式网页的图片上传需要经过运行时可用的 OpenTrek 上传与附件引用接口。工作流已经具备读取 `attachments` 与图片 URL 的能力；产品端只会在取得安全的运行时上传协议后开放该链路。

## 9. 结果 Metadata 合同

每个工作流结果都由统一结果渲染节点返回正文和 Metadata。前端只依据受控字段决定展示与跳转：

```text
intent   当前主要意图
action   可执行的前端动作，或邀请状态
ragUsed  是否使用了可验证检索结果
sources  检索来源列表
```

环境图片支持为非 RAG 路径，固定返回：

```text
intent = environment_support
action = none
ragUsed = false
sources = []
```

图片 URL、平台临时签名地址、Trace、会话标识和内部附件对象不进入回复 Metadata，也不向浏览器历史记录暴露。

## 10. 轻支持工具

### 每日记录

用户可记录当天能量、情绪、身体感受和备注。记录会在后续对话中作为用户主动提供的当下状态参考，不作为诊断信息。

### 轻计划

轻计划最多保留三件当天真正需要的小步骤。空状态会引导用户先放入一件五分钟内可开始的事，完成、删除和推迟都保持低压力。

### 轻专注番茄钟

支持 5、10、15、25 分钟预设，也支持 1–90 分钟自定义时长。对话打开计时时会直接聚焦、展开并高亮该工具。

计时开始后，用户切换到周期、对话或其他应用内页面时，右下角显示全局迷你计时器：可查看剩余时间、暂停或继续，点击可返回并展开完整番茄钟。在轻支持工具页内不会重复显示迷你计时器。

### 环境微调、感官减载与微运动

工具页还提供固定的环境微调、感官减载和一到三分钟微运动建议。每张工具卡片默认收起，显示标题与简要状态；点击或悬停后可展开，避免页面在大屏幕上留下不必要的空白。

## 11. 安全边界

涉及自伤、自杀、伤害他人、正在实施危险行为或无法保证人身安全的内容，优先进入危机支持路径，不再继续普通任务、周期、工具或图片环境建议。

系统不提供医疗诊断、自伤方法或危险操作。周期信息、每日记录、图片观察和知识库内容都只能作为有限支持上下文，不能替代专业医疗或紧急支持。

## 12. 当前发布与联调原则

工作流修改、前后端兼容和平台发布是三个独立步骤：

1. 在工作流画布完成节点、条件、结果渲染和单节点调试；
2. 在前后端完成 Metadata、action、工具跳转和附件传输兼容；
3. 发布工作流版本后，再用真实网页进行文本、动作确认、工具跳转和图片路径联调。

只有完成对应链路验证后，才将该能力视为可在正式用户体验中使用。
