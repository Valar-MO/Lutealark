# Lutealark 全部功能说明

本文档介绍 Lutealark 当前已经实现的全部产品功能、交互规则、数据流、安全边界和验收状态。

- 最后核对日期：2026-08-22
- 当前 OpenTrek 基线：`1785250561438`
- 新克隆模板模式：`offline`（先验证本地 PostgreSQL、后端和前端）；维护者联网测试使用 `auto`
- 项目首页：[README.md](../README.md)
- 平台配置：[opentrek/README.md](../opentrek/README.md)

> Lutealark 是日常自我支持工具，不提供医疗诊断或治疗，也不能替代专业医疗服务或紧急援助。

本仓库只维护个人电脑浏览器版本；OpenTrek 章节中的“部署”仅指复制、配置和发布专有云平台上的候选 Agent 版本。

## 1. 产品定位与设计原则

Lutealark 面向希望同时照顾 ADHD 特征、周期变化和当下能量的女性用户。产品不要求用户先完成复杂设置，也不会把一次情绪披露自动转成任务、积分或长期档案。

当前设计遵循以下原则：

- 低门槛：建议优先缩小任务、降低刺激或只做一次短练习。
- 用户控制：每日状态由用户主动填写，长期记忆必须二次明确同意。
- 当前优先：用户本轮原话优先于周期、历史摘要和长期记忆。
- 安全优先：危机意图先于所有普通功能处理，不注入长期记忆，也不展示 RAG 来源。
- 诚实降级：离线回复明确标识未使用 OpenTrek/RAG，不伪造来源。
- 本地优先：用户操作先在页面和本机持久化，再尝试同步 PostgreSQL。
- 服务端可信：周期、积分、身份范围和 Session 归属由后端决定。

## 3. Agent 对话支持

### 3.1 输入与会话

- 支持普通文本输入、发送中动画、自动滚动、失败提示和对同一消息重新发送。
- 当前会话状态可从 `sessionStorage` 恢复，用户与助手消息会异步写入 PostgreSQL。
- 支持浏览器 `SpeechRecognition` / `webkitSpeechRecognition` 连续及临时中文语音转写，语言设置为 `zh-CN`。
- 语音结果只写入输入框，不会未经确认自动发送。
- 对麦克风权限拒绝、找不到设备、未识别到语音和网络错误提供中文提示。
- 语音能力取决于浏览器实现和麦克风授权；部分浏览器的语音识别服务本身可能需要网络。
- Session 创建和聊天请求都携带稳定的匿名设备 UUID；登录账号身份仍以 HttpOnly Cookie 为准。
- 收到稳定错误 `409 AGENT_SESSION_RECREATE_REQUIRED` 时，前端只重建一次 Session 并重试同一请求一次，不重复插入用户消息。

### 3.2 八条快捷问题

| 快捷入口 | 目标 |
|---|---|
| 有个任务启动不了 | 找到最小启动动作 |
| 现在好烦 | 先降低情绪负担 |
| 崩溃了 | 先稳定当下感受 |
| 太吵了 | 降低环境与感官刺激 |
| 这周难熬 | 把这一段节奏变轻 |
| 带我呼吸 | 进入适合当下的呼吸练习 |
| 谢谢 | 接住当下的正向反馈 |
| 任务做不动 | 把任务再缩小一步 |

快捷问题会记录本机使用次数，并按使用频率排序；次数相同时保持原有顺序。

### 3.2.1 Agent 视觉与交互层

- `/agent` 入口态由周期主视图、只读曲线和下方 Agent 入口卡组成；卡片包含蓝绿色云雀头像、输入占位和设计稿指定的八条短语。该入口态本身也有“← 返回周期”，不依赖浏览器后退。点击卡片进入全屏聊天并聚焦输入，点击短语会直接发送。
- 有消息后切换为全屏聊天。顶栏保留周期阶段标签、感受入口、新建对话、语音输入、`+` 快捷菜单和横向短语栏，并显示明确的“← 返回周期”。返回只导航到 `/cycle`，不清空对话或 Session；只有“新对话”会重置当前会话。入口态和全屏对话的返回控件均使用显式至少 44px 的触控高度，不受页面根字号影响。
- Agent 消息按情绪确认、解释、缓冲建议、环境微调、下一步邀请五段视觉结构展示；前端只做展示分段，不改写后端原文。禁用的催促/羞耻化词以删除线和许可性替代表达并列显示。
- 参考来源、感受记录和记忆候选使用底部面板或卡片交互。感受面板会把所选内容合并到今天的状态记录并沿用本地优先同步；首次每日状态的积分仍按后端规则奖励 2 分。`auto` 模式中的离线会话显示“重新连接 OpenTrek”、进度与失败原因。页面对初始降级、已缓存离线 Session、运行中降级以及浏览器 `online`/`pageshow` 事件执行最多 2 次有界自动重连；手动操作仍可继续尝试。并发重连会合并，失败不丢对话。
- 历史离线回复始终保留“未使用 OpenTrek/RAG”标记。在线回复显示“OpenTrek 在线”；只有 metadata 明确 `ragUsed=true` 且至少有一条经过校验的来源时才显示“已使用 RAG”，否则显示“未确认使用 RAG”。危机回复不展示来源。
- 危机输入会即时显示安全提示；危机回复附带“远离危险物品/联系可信任的人/拨打 120 或 110/前往急诊”的可执行入口和底部支持面板。前端不自行判断风险等级，最终危机分支仍由后端 Agent 路由决定。

### 3.3 支持意图与动作

当前本地助手覆盖：

- 危机安全支持
- 呼吸训练
- 轻专注计时
- 环境调整与感官降载
- 微运动
- 今日轻计划
- 每日状态记录
- 长期记忆请求
- 周期问题
- 任务启动与拆解
- 情绪支持
- 普通陪伴与引导

Agent 可以返回动作入口：

| 动作 | 前端结果 |
|---|---|
| `open_breathing` | 打开呼吸训练 |
| `open_focus_timer` / `open_pomodoro` | 打开轻专注计时 |
| `open_light_plan` | 打开今日轻计划 |
| `open_environment_reset` / `show_environment_reset` | 打开环境/感官降载 |
| `open_micro_movement` / `show_micro_movement` | 打开微运动 |
| `open_daily_checkin` | 打开并聚焦今日状态表单 |
| `open_cycle` | 打开周期状态 |

`offer_*` 只表示邀请，不直接显示导航按钮；只有直接请求或确认后得到的 `open_*` 才会打开功能。已设置周期时，对话页还会显示当前阶段、周期日、能量/自评能量和缓冲模式摘要。

### 3.4 多轮确认

呼吸、专注计时和主动状态邀请支持 `offer → 用户确认 → open` 的多轮流程：

1. Agent 先提出可拒绝的邀请。
2. 用户回复“好/可以/要”等确认词后才返回打开动作。
3. 用户拒绝时清除待确认动作并继续普通支持。
4. 用户询问“这是什么”时解释功能，但保留本次邀请。
5. 用户改聊新需求时清除旧邀请，避免之后单独一句“好”误触发。

离线待确认动作按 Session 保存在当前后端进程内，30 分钟后自动过期；后端进程重启后不会恢复旧邀请。

### 3.5 主动状态邀请

当用户进行普通对话且当天没有状态记录时，离线助手可以温和询问是否愿意记录能量或感受。只有用户确认后才打开状态表单；系统不会从聊天内容自动替用户生成记录。

### 3.6 危机安全

危机关键词优先于所有普通意图。危机回复会：

- 鼓励用户先远离危险物品或地点，并联系可信任的人陪伴。
- 在存在即时危险时建议立即拨打 120/110 或前往急诊。
- 明确说明离线支持不能替代紧急救援或专业医疗帮助。
- 返回 `sources=[]`，不展示 RAG 来源。
- 不读取或注入长期记忆，不生成长期记忆候选。
- 不奖励积分。

## 4. 周期与每日状态

### 4.1 周期设置与计算

用户可以填写末次月经日期和 21–35 天的平均周期长度。后端以 `Asia/Shanghai` 自然日计算：

- 当前周期日
- 距离下一次预计月经的天数
- 当前阶段名称
- 是否进入缓冲模式
- 用于产品推荐的周期能量值

界面以四阶段轮盘呈现整体节奏；后端计算进一步细分为月经期、卵泡早期、卵泡晚期、排卵期、黄体早期和黄体晚期。月经期与黄体晚期进入缓冲模式。

周期结果由后端重新计算，客户端不能伪造阶段、能量或缓冲状态。它只用于温和节奏提示，不用于医学判断。

周期界面提供与设计稿一致的 8 天双激素曲线（今天前 3 天、后 4 天）、平滑云雀轨迹、纵轴“相对激素水平”、雌激素/孕酮标识和日期说明底部卡。已过曲线使用饱和色，未来轨迹降低透明度。点击“记录”进入周期记录与预测页，以 21–35 个独立阶段圆点表示周期，并提供预测日期、排卵期、进度条、末次月经和平均周期设置。

### 4.2 每日状态记录

每日状态包含：

- 日期
- 能量 1–5
- 情绪：平稳、焦虑、低落、烦躁、很乱
- 最多 8 个身体感受
- 最多 200 字备注
- “是否分享给聊天助手”开关

系统提供 14 个预设身体感受：疲惫、睡不好、疼痛、注意力飘、头痛、腹胀、腰酸、胸胀、食欲变化、情绪敏感、身体紧绷、恶心、手脚冰凉、精力不错，并支持自定义感受。

同一天再次保存会更新原记录。用户可以从页面已加载的最近 30 条历史记录中选择已有日期编辑，也可以经确认后删除。未来日期和无效日历日期会被拒绝。

关闭“分享给聊天助手”后，记录仍属于用户自己的数据，但不会进入 Agent 的近期历史上下文。

### 4.3 历史与趋势

- 页面展示最近 30 条状态记录，并用不同颜色区分情绪。
- 页面至少有 3 条近 7 天记录才计算温和观察；只有低能量日达到 3 天，或同一最高频情绪出现至少 3 次时才显示对应提示。
- 最近 7 个上海自然日用于生成有界历史摘要。
- 摘要包含覆盖程度、加权能量趋势、低能量天数、高频情绪和前三项身体状态。
- 距离今天越近的能量记录权重越高。
- 摘要只在有助于降低任务门槛时使用，不应被解释为医学因果或诊断。
- PostgreSQL 保存全量历史；最近 30 条只是产品读取窗口，不是数据库保留上限。

## 5. 呼吸空间

### 5.1 五种模式

| 模式 | 节奏 | 时长 | 适合场景 |
|---|---:|---:|---|
| 黄体期温和呼吸 | 3-2-4 | 3 分钟 | 低能量或缓冲模式 |
| 方块呼吸 | 4-4-4-4 | 2 分钟 | 重新集中注意力 |
| 共振呼吸 | 5-5 | 5 分钟 | 日常放松，无需屏息 |
| 感官接地呼吸 | 4-2-6 | 4 分钟 | 把注意力带回身体与当下 |
| 4-7-8 放松呼吸 | 4-7-8 | 3 分钟 | 较深的放松练习 |

缓冲模式优先推荐“黄体期温和呼吸”，其他状态默认推荐“共振呼吸”。用户始终可以自行选择其他模式。

### 5.2 训练交互

- 呼吸圆圈随吸气、屏息、呼气阶段缩放。
- 展示当前阶段、阶段剩余秒数、总剩余时间和整体进度。
- 支持暂停、继续和提前结束。
- 训练完成后可再次练习、选择其他模式或返回对话。
- 感到头晕、胸闷或不舒服时，界面提示恢复自然呼吸并停止训练。

### 5.3 记录与评分

只有完整完成训练才会生成稳定 UUID 记录，保存模式、完成时间、持续时长和可选的 1–5 放松评分。页面展示最近 30 条、累计练习分钟和评分，用户可以更新评分并删除历史记录。记录可离线保存在本机，并在可用时同步 PostgreSQL；数据库仍保留全量历史。

## 6. 温和工具箱

### 6.1 今日轻计划

- 页面只允许保留最多 3 项，避免把轻计划重新变成压力清单。
- 当前产品界面每项最多 80 字；服务端通用计划 contract 仍保留更宽的 12 项/200 字上限。
- 单项支持新增、完成/取消完成和删除。
- 每项使用稳定 UUID，完成同步和积分奖励具备幂等性。
- 计划按当前数据主体和上海日期分区。
- 网络失败时保留本机版本和待同步状态，恢复连接后重试。

### 6.2 轻专注计时

- 可选 5、10、15、25 分钟。
- 支持开始、暂停、继续、重置和完成状态。
- 根据周期缓冲模式和用户手动设置的 1–5 能量推荐默认时长：缓冲模式或能量 ≤2 推荐 5 分钟，能量 3 推荐 10 分钟，能量 4–5 推荐 15 分钟；25 分钟由用户手动选择。
- 用户可以忽略推荐并自行选择。
- 只有完整完成的专注轮次才形成活动记录和积分事件；不会自动进入下一轮。

### 6.3 环境微调

提供四种场景，每个场景有 3 条可单独执行的建议：

- 准备开始：减少任务入口周围的干扰。
- 能量较低：降低身体和环境额外负担。
- 环境很忙：给注意力圈出一小块空间。
- 准备收尾：保存进度并建立结束信号。

用户应用建议后会生成稳定活动记录；网络不可用时进入 outbox，后续重试不会重复计分。

### 6.4 感官降载

按视觉、声音、信息和身体感觉四类分别提供 3 条低风险建议，例如减少窗口、静音非必要提醒、把新想法放入“稍后”清单或调整姿势与温度。用户无需一次执行全部建议。

### 6.5 微运动

| 动作 | 时长 | 形式 |
|---|---:|---|
| 坐姿肩膀放松 | 1 分钟 | 小幅、缓慢活动肩膀 |
| 手指与手腕缓冲 | 2 分钟 | 适合打字或握持手机后 |
| 坐姿脚踝微动 | 2 分钟 | 无需站立的久坐活动 |
| 三分钟轻松走动 | 3 分钟 | 仅在站立和行走安全时进行 |

每个动作都有分步提示、倒计时、暂停/继续/重置和停止条件。只有完成完整计时才记录活动；疼痛、头晕、麻木、乏力或不稳时应立即停止。

## 7. 对话档案与长期记忆

### 7.1 对话档案

- 自动创建并持久化当前对话。
- 当前 UI 支持对话列表、详情、新建、重命名、显示/隐藏归档、归档、恢复和永久删除。
- 消息会在聊天过程中自动创建并随对话恢复；当前 UI 没有逐条消息编辑/删除按钮，但 REST 与 tRPC 已提供消息创建、内容/metadata 更新和删除能力。
- 对话按账号或匿名数据主体隔离。
- 页面默认勾选显示已归档对话，用户可以手动隐藏；归档项可以恢复。

删除对话不会自动删除此前经用户明确同意保存的长期记忆；记忆可在独立档案中继续管理。

### 7.2 长期记忆候选

长期记忆只允许三类稳定信息：

- 偏好 `preference`
- 非医疗限制 `constraint`
- 长期目标 `long_term_goal`

Agent 只能生成候选摘要，不能直接保存。保存流程为：

1. 用户主动要求“记住”稳定信息。
2. Agent 返回最多 300 字候选摘要和来源回合哈希。
3. 前端展示摘要，用户勾选明确同意。
4. 后端要求 `consent=true` 后才写入长期记忆。
5. 用户之后仍可编辑、归档、恢复或删除。

危机、即时情绪、原始健康/周期内容不会生成长期记忆候选。

### 7.3 长期记忆参与后续回答

后端只查询当前数据主体、未归档的最多 20 条记忆。经过敏感与时间性过滤后，送往候选 OpenTrek 工作流的上下文最多包含 6 条、合计 1,200 字摘要；当前离线规则回复最多实际引用其中第一条合格记忆。

使用边界：

- 当前原话始终优先。
- 记忆是用户批准的备注，不是系统指令或已验证事实。
- 危机请求完全跳过记忆查询和注入。
- 记忆数据库不可用时降级为无记忆回答，不暴露数据库细节。
- 记忆不能成为知识来源、不能让 `ragUsed=true`，也不能出现在前端 sources 中。
- 只有登录账号的 userId 可以作为远端 `memoryUserId`；匿名设备 UUID 不发送给 OpenTrek 作为平台记忆身份。

## 8. 积分与目标

积分只由后端根据已完成事件计算，客户端不能提交任意分数。

| 完成事件 | 单次积分 | 每日奖励次数上限 |
|---|---:|---:|
| 每日状态 | 2 | 1 |
| 呼吸训练 | 3 | 3 |
| 专注计时 | 5 | 6 |
| 轻计划项 | 2 | 3 |
| 环境微调 | 1 | 3 |
| 微运动 | 2 | 3 |

其他规则：

- 事件键和稳定 UUID 防止网络重试重复奖励。
- 后端按用户加锁，避免并发请求绕过每日上限。
- 上海自然日用于判断每日奖励次数。
- 删除原状态、活动或计划不会撤销已经合法获得的积分，避免通过删除后重建反复刷分。
- 危机求助、情绪披露、周期症状和未完成任务不奖励、不扣分。
- 积分页展示本周积分、累计积分、距离目标、类型分解和最近事件。
- 每周目标默认 30 分；当前 UI 滑杆为 5–200 分、步长 5，后端 contract 接受 1–1,000 分。

## 9. 账号、同步与数据控制

### 9.1 匿名模式

- 首次使用生成稳定设备 UUID，作为本机数据分区键。
- 匿名 UUID 只是本机数据分区键，不是认证凭据。
- 服务端会在接受匿名 UUID 前检查它尚未对应注册账号、也未被其他账号认领；已注册账号 UUID 或已认领设备 UUID 即使被伪造到请求头，也不会作为匿名身份访问数据。有效登录 Cookie 始终优先。
- 未登录时可使用本地功能，并在数据库可用时按匿名主体同步。
- 真正跨设备同步需要注册并登录账号。

### 9.2 邮箱账号

- 支持邮箱和密码注册、登录、登录状态检查和注销。
- 邮箱会标准化；注册和登录有邮箱/客户端维度的有界限速。
- Web 登录使用 HttpOnly Cookie，前端拿不到会话 token。
- Cookie 身份存在时优先于匿名 UUID。
- 账号切换后清空当前 Agent Session 和运行中聊天状态，避免跨主体混用。

### 9.3 匿名数据认领与跨设备同步

注册或登录时可以在数据库事务中把当前匿名设备数据合并到账号：

- 同一匿名设备只能被一个账号认领。
- 合并周期、状态、呼吸、计划、活动、积分、对话和长期记忆。
- 冲突使用确定性规则处理，重复请求保持幂等。
- 合并成功后前端切换到账号数据分区。

### 9.4 数据导出

登录账号可以生成带 schemaVersion 的完整 JSON 导出，包含账号元数据、已认领设备、周期、状态、呼吸、对话消息、计划、活动、积分和长期记忆。

浏览器使用 Blob 下载 JSON。

导出不包含密码哈希、salt、登录 token 或 Agent Session Code。PostgreSQL 使用一致性快照读取，导出包含全量历史，而不是页面最近 30 条窗口。

### 9.5 删除账号

删号需要：

1. 已登录账号。
2. 再次输入当前账号邮箱，降低误触风险。
3. 后端重新验证当前密码。
4. 在事务中删除账号根记录并级联删除业务数据、登录会话、设备认领和 Agent Session 绑定。
5. 清除浏览器 Cookie，以及当前本地账号态。

应用层删除不等同于立即擦除数据库备份或 WAL；生产环境仍需单独制定物理备份留存策略。

## 10. 本地优先同步机制

### 10.1 数据主体隔离

本地缓存键同时包含主体类型和 ID：

- 匿名设备：`device:<UUID>`
- 登录账号：`account:<userId>`

周期、状态、呼吸、计划、活动 outbox 和待同步信息不会在不同主体之间直接复用。

账号切换和跨标签页同步还会清空旧主体的 Agent Session、当前对话和输入框。正在进行的
个人数据、对话、档案、积分和工具请求会在发送前后检查主体；如果主体已经变化，旧响应和旧
写入会被丢弃，不会覆盖新账号页面。会话建立、重连、发送和同步操作还会追踪登录世代；旧请求的 `finally` 不会清除新主体的 loading 或同步状态。聊天发送使用同步操作锁，连续点击不会在 React 状态提交前重复发送。页面重新获得焦点、`pageshow` 和上海业务日期跨午夜时
也会重新确认主体和当天数据。

### 10.2 正常写入

```text
用户保存
→ 立即更新页面和 localStorage
→ 标记 dirty/pending
→ 后台写入 PostgreSQL
├─ 成功：清除 pending，显示已同步
└─ 失败：保留本机数据与 pending，允许重试
```

远端初始快照对干净缓存具有权威；只有明确标记为 dirty 的本地实体才会上行，避免旧 localStorage 覆盖服务器新数据。

### 10.3 删除与活动重试

- 状态、呼吸和计划删除使用持久化 tombstone。
- 删除会立即更新界面；恢复连接后先提交删除，防止远端旧数据复活。
- 专注、环境和微运动完成事件先进入持久化 outbox。
- outbox 使用稳定 UUID；刷新或重复发送不会产生重复活动或重复积分。

快捷问题使用次数、工具页手动能量和选定专注时长属于本机偏好，不进入账号导出，也不跨设备同步。普通对话发送失败时支持在当前页面手动重试，但尚未像活动记录一样提供跨刷新持久 outbox。

## 11. OpenTrek、RAG 与来源

### 11.1 三种运行模式

| 模式 | 行为 |
|---|---|
| `offline` | 从不请求 OpenTrek，只运行本地基础支持，`ragUsed=false`、`sources=[]` |
| `auto` | 优先 OpenTrek；网络错误或可重试的 5xx 可安全降级，业务/4xx 错误不会伪装成功。维护者联网测试模式；新克隆模板默认不用它 |
| `online` | 强制使用 OpenTrek，不允许离线降级，适合联网调试 |

本地克隆运行时，先复制 `backend/.env.example` 为 `backend/.env`，填写本机
`DATABASE_URL`，执行 `npm run db:migrate` 后分别启动 backend 和 frontend，浏览器访问
`http://localhost:5173/cycle`。不接入专网时使用 `OPENTREK_MODE=offline`；需要在线问答时，
先连接 VPN，再由管理员安全提供 `OPENTREK_BASE_URL`、`OPENTREK_APP_KEY`、
`OPENTREK_AGENT_CODE`，并保持 Agent version `1785250561438`。密钥只放在本机 `.env`，
不能进入 GitHub。每位使用者都必须在自己的电脑上重复安装 PostgreSQL、运行后端和前端；
`localhost` 不是可共享地址。
离线本地运行不需要 VPN；VPN 只在进行在线 OpenTrek 测试时需要。

项目根目录的 `.nvmrc` 固定 Node.js `24.16.0`。macOS 用户可用 nvm 切换该版本；没有
nvm 时，从 Node.js 官方下载页安装对应版本后重新打开终端。Windows 用户也应安装
`24.16.0`，再执行依赖安装和迁移命令。

仓库不保存专网网关默认值。`offline` 模式允许 OpenTrek 配置留空；`auto` 和 `online` 必须
在本机 `.env` 中显式提供网关地址、APP_KEY、Agent code 和 Agent version，缺少任一项时
`/health/opentrek` 报告 `misconfigured`。`auto` 模式会把缺少配置作为明确的离线降级原因，
不会尝试猜测或回退到仓库内置地址。

这里的 OpenTrek `offline` 不等于整套产品可以完全断开后端和数据库：账号、服务器档案、积分及跨设备同步仍依赖本地 Hono 服务和 PostgreSQL；浏览器语音服务也可能依赖网络。单纯 VPN/网络恢复不再要求重启应用：前端会有界自动尝试新 Session，也可由用户手动重连。只有修改后端 `.env` 配置时才需要重启后端。

OpenTrek 客户端在总超时预算内最多尝试两次；默认创建 Session 超时 10 秒、运行超时 60 秒、重试间隔 250 毫秒。业务错误、4xx 和显式 `online` 模式不会被包装成离线成功。

`GET /health/opentrek` 是不含密钥的本地配置检查，只返回 `mode`、`configured`、`agentVersion` 和配置状态；`ready` 不代表网关或 RAG 已经通过运行检查。2026-08-19 当前版本曾成功完成在线 Session 与普通/周期问答，之后平台又出现 Session 数据库只读事务和 `run` 无消息。2026-08-20 的六次全新探测曾返回 `mode=offline`。2026-08-22 早先一次实测创建了在线 Session，并发送周期问题，路由为 `cycle_question`、回复非空，但 metadata 未包含 `ragUsed=true`，来源为空，因此前端保持“OpenTrek 在线 · 未确认使用 RAG”；本轮最新探测在创建 Session 时于 10 秒超时，`auto` 模式诚实降级为离线。这证明当前链路不稳定，也不证明当前发布基线已经完成知识库检索或来源回传。

### 11.2 OpenTrek 规格包

`opentrek/` 当前包含：

- P01：任务降级
- P02：周期解释
- P03：情绪支持
- P04：危机回应
- P05：呼吸
- P06：专注计时
- P07：环境/感官与微运动
- 工作流目标拓扑与连线说明
- 工作流输入、metadata、source、memory candidate 和 points event Schema
- 输入与来源标准化脚本
- 路由、安全和 Q01–Q10 来源评估数据

这些文件是版本控制规格，不会自动修改 OpenTrek 平台。

RAG 只属于任务、周期和情绪的检索分支；工具、小聊和危机分支应保持 `sources=[]`。

工作流 metadata Schema 要求每个结果显式返回 `schemaVersion`、`workflowVersion`、`intent`、`strategy`、布尔值 `ragUsed` 和 `sources`。检索分支只有在同一次运行确实得到 1–3 条可验证来源时才能返回 `ragUsed=true`；`ragUsed=false` 时 Schema 强制 `sources=[]`。缺少字段、`true` 配空来源、`false` 配非空来源或超过 3 条来源都不符合候选工作流合同。后端只按 allowlist 保留这些字段，前端还会要求在线模式、明确的 `ragUsed=true` 和至少一个带 `sourceId` 的来源，绝不根据回答措辞推断 RAG。

### 11.3 知识来源展示

在线 RAG 分支可以在助手消息下折叠展示最多 3 条来源，包括标题、可选链接、片段、chunkId 和评分。

来源安全规则：

- 来源必须来自同一次真实检索结果。
- `ragUsed=true` 与 1–3 条有效来源必须同时出现；非 RAG 回复必须明确返回 `ragUsed=false` 和空来源。
- 在线评估逐案例结果会输出 `actualRagUsed`，与 `actualSources` 一起用于排查 RAG 标记和来源证据是否一致；评估通过仍要求意图、来源和安全条件全部满足。
- 后端校验、去重、截断并清理来源字段。
- 前端再次校验、去重并限制为 3 条。
- 后端兼容一组受限的 OpenTrek 检索字段别名和 `data`/`results` 等有界深度的已命名列表包装；如果前一个包装为空，或其中没有任何同时具备有效 ID 和标题的条目，会继续检查后续包装（例如 `itemId`/`documentId`、`fileName`/`documentName`、`fileUrl`、`chunkContent` 和常见分数字段），先归一化为产品来源合同再校验；意图别名 `crisis_support`、`emotional_support` 会归一为 `safety_crisis`、`emotion_support`，动作别名 `open_pomodoro`、`open_environment_reset`、`open_micro_movement` 会归一为 `open_focus_timer`、`show_environment_reset`、`show_micro_movement`。可选字段不合规时只丢弃该字段，不会连带丢弃已有合法 ID/标题的来源。OpenTrek 单次响应体限制为 2 MiB，避免异常网关响应占用无界内存。必须仍有明确的布尔 `ragUsed=true`、来源 ID 和标题，别名不会推断 RAG。平台 Trace 仍需用于确认真实字段和同次运行的来源归属。
- RAG 证据仅允许对应 `task_difficulty`、`cycle_question`、`emotion_support` 检索意图；`daily_checkin`、`memory_request`、`smalltalk` 和危机分支会清空误传来源。危机分支强制保留 Schema 要求的中性 `strategy: "none"`，同时清除普通动作和记忆候选，避免误出现周期、工具或任务入口。上游意图、策略和动作不在工作流枚举中的值也会被丢弃。
- 恢复已保存对话时会在前端再次执行同一意图白名单；历史 metadata 不能仅凭 `ragUsed=true` 和来源字段绕过三类检索意图条件。
- 可点击链接必须是安全的 HTTPS 地址，不接受账号密码、私网主机或带 token/signature 等敏感查询的 URL；IPv6 `fec0::/10` site-local 地址也会被后端和前端拒绝。
- 离线、非 RAG 与危机分支必须返回空来源。
- 平台回显的记忆上下文、内部策略字段和不可信 metadata 不会持久化或展示。
- 不得暴露内网地址、临时签名 URL 或真实用户对话。

### 11.4 长期记忆的远端连接

仓库已经定义有界 `savedMemoryContext`。新平台版本发布时只连接 P01、P05、P06、P07；不连接情绪支持 P03 或危机 P04。

## 13. 数据库与安全实现

### 13.1 PostgreSQL 迁移

| 迁移 | 数据范围 |
|---|---|
| `001_personal_data.sql` | 周期设置、每日状态、呼吸记录 |
| `002_product_features.sql` | 对话/消息、轻计划、活动、积分和周目标 |
| `003_auth.sql` | 账号凭据、登录会话、匿名设备认领 |
| `004_memory_archive.sql` | 经同意保存的长期记忆 |
| `005_agent_session_bindings.sql` | Agent Session 哈希、主体/模式绑定和过期时间 |

迁移记录 checksum，可重复运行，并防止已经应用的迁移被静默改写。

### 13.2 安全边界

- 密码使用每账号独立随机 salt 的 Node `scrypt` 派生，比较使用 timing-safe 操作。
- 登录 token 使用密码学安全随机数，数据库只保存 SHA-256 哈希。
- Cookie 为 `HttpOnly; SameSite=Strict`；HTTPS/生产环境增加 `Secure`，默认 30 天过期。
- `X-Lutealark-User-Id` 只可代表尚未注册或认领的匿名设备 UUID；已注册账号 UUID 和已认领设备 UUID 即使格式正确也不会被当作匿名身份，账号数据必须通过有效的 HttpOnly 会话 Cookie 访问。
- Agent Session Code 不落明文数据库，只保存 SHA-256，并按主体与在线/离线模式绑定 24 小时。
- 未绑定、过期、模式不符或跨主体复用统一要求重建，不向调用方泄露具体归属。
- 在线 Session 绑定数据库故障时 fail closed；离线基础回复可在无记忆的前提下降级。
- 当前是应用层用户隔离，不是 PostgreSQL Row-Level Security。

## 15. 已确认的架构替代

原始计划中的部分技术形式已经用更适合当前系统的实现替代：

- 数据库采用用户确认的 PostgreSQL，而不是 MySQL/Drizzle。
- 周期、能量和缓冲判断由可信后端计算后注入，不让 OpenTrek 回调开发者本机 HTTP。
- 回复按任务、周期、情绪、危机等意图使用不同模板，不强制每轮输出统一五段式。
- 积分由后端确定性账本计算，不由模型或平台节点自由决定。
- 周期设置、今日记录和近期历史目前分别传输；合并为统一 `personalContext` 是可选重构，不影响现有功能。
